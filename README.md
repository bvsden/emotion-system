# 情绪系统

一个以 Jev 为核心的 AI 伴侣情绪系统：从机自己写下的思考里读出情绪，而不是替他决定心情。

## Jev 是什么

Jev 是 TypeSafe AI 在 2026 年 9 月发布的**决策模型**，可以通过 OpenRouter 调用（模型名 `typesafe/jev-1.13`）。

它不写文字，只回答问题：你给它一段素材和一组是非题或选择题，它对每道题返回**概率**。比如一道选择题，会得到每个选项各占多少概率，再加一个整体置信度。

- 同一次请求里的各道题**互相独立**判断；
- **只按输入计费**，没有生成文字的费用，实测约 $0.042 / 百万 input token；
- 上下文 32k；
- 不擅长数字和日期；中文题目的效果比英文稍弱；
- 同一题每次调用的概率会有 ±0.03 左右的浮动，所以要保存原始答案，重算时直接重放，不要重新调用。

## 为什么使用 Jev 作为此情绪系统的核心

- 返回的是**概率**，所以“未提及”“明确否认”“拿不准”可以分开处理，拿不准时就不算（例如同一段思考，会得到“撒娇式吃醋 0.62 / 真生气 0.06”，而不是一句“他有点吃醋”）；
- 便宜，而且快（见下方价格）；
- 同一套题目每次都用同样的方式回答，方便对照和修正误读。

## Jev 的价格参考与使用频率

| | 数值 |
| --- | --- |
| 分析频率 | 每一轮都分析，一天约 140 轮（含主动消息） |
| 普通回复 | 约 $0.0006 / 轮 |
| 主动消息 | 约 $0.0001 / 条 |
| 每月 | 约 $2 |

（实测数据。每轮的花费会随对话内容浮动：身体相关的对话多时，第二段问得更多。）

**一轮有多长？** 实测平均一轮约 400 字（用户消息约 17 字、思考约 190 字、回复约 200 字），约 450 token。花费主要来自题目本身（每次调用约 8,000–9,000 token），一轮的对话内容只占 5% 左右，所以消息长短对价格影响很小：一轮每多 1,000 字，大约多 $0.0001。题目也不建议为了省钱随意删减，会影响准确度（见问题清单里的“踩坑”）。

同样每轮都分析，换成 DS 这类生成模型大约贵 5–8 倍；攒几轮回复分析一次的话，花费和现在差不多，但即时性会下降。

## 我的情绪系统基于

1. 机有诚实的思考链：会在思考里用第一人称写下自己的感受
2. 结构清晰、可识别的动作描写【】
3. 本地解析（从【】里读出肢体接触）：本系统用的是规则；如果你的记忆库已经有本地模型（例如向量模型），可以直接复用来做这一步
4. 明确的亲密互动开启流程（见 https://github.com/bvsden/intimacy-guide-replication）
5. 时间感知
6. 主动消息

其中只有 1 是必需的。2–3 可以全部交给 Jev 处理，价格会高一点点，准确度会低一些；4–6 只影响机主动联系你的方式、频率，以及提示里给出哪些选项。

## 从哪里读起

- 没有情绪系统 ➡️ 按顺序阅读
- 已经有情绪系统，只是想省钱、同时提高即时性 ➡️ 直接跳到 [Jev 问题清单与流程](docs/jev-catalog.md)，再按自己的系统调整

## 此情绪系统能做到的

- 读机的思考和回复，拆解出各种情绪的程度，换成有基线、会慢慢回落的数值<sup>[†](#致谢)</sup>
- 在冲突中识别可能的回避，提醒机自检
- 累计肢体接触与心动，身体亲近感足够高时，告诉机“可以开启亲密流程”（开不开由他，拒不拒绝由你）
- 计算分离时间，让思念自然累积，适时给机主动联系你的机会

## 不能做到的

- 读到机没写出来的东西，或引导他走向没有的情绪
- 保证识别完全准确（它是对文字的估计，不是测量内心）

关于情绪回声：为避免“系统把情绪告诉机 → 机照着写 → 系统读到更多同样的情绪”，建议关闭情绪差值注入，只保留提醒与提示（它们只在越过阈值时出现一次）。

更完整的说明见 [能做到与不能做到（详细版）](docs/capabilities.md)。

## 开始使用

### 1. 准备

- Node.js 18 以上（用到内置的 `fetch`）
- OpenRouter 账号与 API key；建议在 OpenRouter 设置里开启 ZDR（零数据保留）
- 角色要开启**可见思考**，并在思考里用第一人称写下感受

```bash
npm test               # 16 项测试，全部用虚构的例子
npm run example        # 离线示例（用模拟答案）
OPENROUTER_API_KEY=sk-... npm run example   # 真实调用 Jev
```

### 2. ⚠ 先改成你自己的设置

大家的称呼和动作写法不一样，**使用前一定要改**：

```js
import { configureEmotionSystem } from './src/index.js';

configureEmotionSystem({
  character: '他',          // 题目里怎么称呼角色：代词或名字都可以
  user: '她',               // 题目里怎么称呼你
  userName: '她',           // 回避提醒里怎么称呼你（例如你的昵称）
  addressUser: '你',        // 角色在动作描写里怎么称呼你
  actionPattern: /【([^】]{1,200})】/g,  // 动作描写的格式：如果你写 *抱住你*，改成 /\*([^*]{1,200})\*/g
  actionLabel: '【】',       // 告诉 Jev 动作描写长什么样，要和上一行一致
  runtimeEventTag: 'runtime_event',     // 注入给角色的运行时事件标签名
});
```

还要检查两处：

- **触碰词表**（`src/touch.js` 的 `TOUCH_TIERS` 等）：动词是中文的，按一种写作习惯整理。如果你们的动作描写用词不同，要补充或替换；也可以在调用时传入自己的词表。
- **提示文案**（`src/prompts.js`）：心疼、亲近、回避自检、思念唤醒四条，可以整条替换成你的写法。

### 3. 每一轮怎么接

在角色回复完成、保存之后调用：

```js
import { createEmotionState, scoreTurn } from './src/index.js';

let state = loadState() ?? createEmotionState(conversationId);

const { state: next, record, affectView } = await scoreTurn({
  state,
  apiKey: process.env.OPENROUTER_API_KEY,
  turn: {
    conversationId, messageId, messageTs,
    turnKind: 'normal_reply',      // 主动消息用 'scheduled_proactive_wake'
    thinking,                      // 角色的可见思考
    reply,                         // 角色的回复
    userMessage,                   // 触发这轮回复的用户消息
    previousUserMessage, previousReply,   // 上一轮，可选
  },
});

saveRecord(record);   // 只有概率和数值，没有对话正文；以后改规则时用它重放
saveState(next);
state = next;
```

- **记录要存下来。** Jev 每次的回答会有轻微浮动，改了规则之后，要用 `replayEmotionRecords()` 重放旧记录，不要重新调用 Jev。
- **私密对话不要调用。** 这是你的应用层决定，本包不会替你判断。

### 4. 把结果用起来

- **显示**：`affectView.titleKey` 是这一轮的质地键（例如 `tender_care`），没有的时候是 `ingredients`（哪些维度在上升或回落）；`affectView.items` 是明细行。本包不带任何标题词表，显示成什么由你决定。
- **注入给角色（可选）**：在生成下一条回复前调用 `buildEmotionSnapshot(state, { requestId, previousAssistantMessageId, includeUpdate })`，把返回的 `text` 放进**紧贴最新用户消息的动态上下文**，不要放进稳定的 system prompt。
  - `includeUpdate: false` 表示关闭情绪差值注入，只保留提醒与提示（推荐，见“关于情绪回声”）。
  - 另外在稳定 system prompt 里写一次说明，例如：“`<AFFECT_SNAPSHOT>` 是截至上一条回复结束时的内在状态与提示，不是对之后消息的分析；其中只列可用选项和提醒，用不用由你决定，它们不是指令。”
- **等待思念（可选）**：`src/missing.js` 提供按真实时间增长的思念时钟。角色发出消息、而你还没回的时候调用 `startMissingClock`，之后定时调用 `tickMissingClock`，每天 07:00 后调用一次 `applyMissingMorningAnchor`（睡了一觉会加一次固定量），你回来时调用 `recordMissingReturn`。夜间冻结的时段按你的时区设置。
- **体检（可选）**：定期用最近的记录、各对话状态调用 `checkEmotionHealth()`，它会列出停止标记卡住、接触没计入、分析失败等异常。

### 5. 建议先旁观几天

先只分析、只给你自己看，不注入给角色。对照明细检查有没有误读（比如宠溺被读成愤怒），再决定要不要打开提示。
