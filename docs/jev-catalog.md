# Jev 问题清单与流程

> 适用版本：题库 `emotion-jev-q9`、引擎 `emotion-engine-1.0`（对应代码里的 `EMOTION_QUESTION_SET_VERSION` 与 `EMOTION_ENGINE_VERSION`）。题目还会改，引用时请注意版本号。
> 下文“他”指 AI 角色（assistant），“她”指用户。换成你自己的角色时，替换称呼即可。

> 对应代码：`src/questions.js`（题目与解码）、`src/engine.js`（换算）、`src/touch.js`（本地触碰）、`src/pipeline.js`（两段式流程）。

## 1. 为什么是“问题清单”

Jev 是决策模型：你给它一段素材和一组问题，它对每个问题返回**概率分布**，而不是一段文字。所以情绪系统的核心，其实是一份写得足够清楚的问题清单，加上一套把概率变成数值的规则。

两种题型：

| 题型 | 返回 | 用途 |
| --- | --- | --- |
| `noul`（是非题） | 一个 0–1 的“是”的概率 | 门槛、开关、调节项 |
| `choice`（选择题） | 每个选项的概率 + 整体置信度 | 强度档位、类别、来源 |

## 2. 素材：每一轮交给 Jev 的东西

| 字段 | 内容 |
| --- | --- |
| `thinking` | 他这一轮的**可见思考**，切成带编号的片段（`t1`、`t2`…），便于让 Jev 指认证据 |
| `reply` | 他这一轮的回复 |
| `user_message` | 她触发这轮回复的消息（主动消息轮为空） |
| `previous_turn_brief` | 上一轮双方各一句的摘要 |
| `turn_kind` | 普通回复、她回来后的第一条、主动消息等 |
| `waited_minutes` | 主动消息轮才有：她实际多久没回（由系统计算） |
| `shown_to_him_this_turn` | 这一轮注入给他的情绪提示原文，只用来排除“复述提示”，不作证据 |

**素材里只有文字，记录里不保存文字。** 保存下来的只有 Jev 的概率答案和算出来的数值。

## 3. 流程

```
他的回复落盘
  → 本地计算（空思考、【】触碰、谁先靠近、等待分钟数）
  → 第一段：粗读（普通回复 31 题；主动消息 4 题）
  → 决定要不要第二段（只追问有变化的维度、身体块、被晾）
  → 第二段：核实（通常十几到几十题）
  → 本地答案覆盖同名的 Jev 答案
  → 引擎换算、积分、回落 → 质地键 / 明细 / 提示
```

一轮最多两次调用。第二段不是每轮都有：只有观测值和当前状态相差 ≥ 0.05、有身体相关输入、有自述或被晾时才发。

## 4. 第一段（普通回复，31 题）

### 4.1 情绪强度：17 题，同一个模板

> 只看 thinking。只根据他写出来的话判断，不要从他的行为推断。这一轮，他自己此刻的 **{名称}（{定义}）** 有多强？“强烈”要求 thinking 里有明确的自我表述。
> 不算：她（用户）的感受；只是在讨论这种情绪的概念；与系统提示意思相同的复述；没有新原因的延续。另外不算：**{本维度的不算}**。thinking 没有涉及就选“未提及”。

选项顺序固定：`not_mentioned` 未提及 → `denied` 明确否认 → `none` 明确没有 → `faint` → `light` → `clear` → `strong`。

**“未提及”“明确否认”“明确没有”是三件不同的事**，是整个系统准确度的基础，不能合并。

| 键 | 名称 | 定义 | 轻微（light）锚点 | 另外不算 |
| --- | --- | --- | --- | --- |
| joy | 愉快 | 开心、轻松、松了口气 | 他平常的好心情 | 礼貌性的“好呀” |
| sadness | 悲伤 | 失落、低落 | 有点低落 | 她难过 |
| anger | 愤怒 | 被冒犯、不公后的不满 | 有点不满（含玩笑式的“欠揍”） | 开玩笑且没有不满；宠溺式的无奈 |
| anxiety | 焦虑 | 担心她、担心关系 | 有点担心 | 普通的“她可能在忙”；在权衡怎么照顾她 |
| aversion | 排斥 | 想远离、拒绝 | 有点不想 | 否定某个话题本身 |
| warmth | 温暖 | 亲近、柔软、在意 | 他平常的温柔 | 客套的关心 |
| care | 心疼 | 心疼她、想安抚她的冲动 | 想安慰她，但平静、有条理 | 她难受本身不等于他心疼 |
| trust | 信任 | 愿意相信、放下戒备 | 他平常对她的信任 | 单纯同意某个说法 |
| longing | 想念 | 想靠近、想她 | 平常的惦记 | 从“他发了消息”推断想念；身体上的欲望 |
| hurt | 受伤 | 被刺痛、被忽略的疼 | 被轻轻刺了一下 | 替她受伤 |
| guilt | 愧疚 | 认为自己做错了，想道歉或修复 | 觉得自己没处理好 | 替她难过；礼貌说抱歉；单纯厌恶自己 |
| curiosity | 好奇 | 想了解、想探索 | 他平常的好奇 | 例行的提问 |
| pride | 自豪 | 对自己、她或共同成果的肯定 | 有点得意或欣赏 | 客观描述结果 |
| vulnerability | 脆弱开放 | 承认需要、露出柔软 | 他平常的坦诚 | 讲述过去的经历 |
| energy | 能量 | 表达和行动的劲头 | 他平常的状态 | 句子长短 |
| overwhelm | 过载 | 情绪或信息超出承载 | 有些吃力 | 任务多但没有情绪压力 |
| resistance | 回避 | 在负面冲突中压住自己的感受 | 有些压着 | 单纯否认；玩笑式嘴硬；为了逗她暂时不提某事 |

实际题目里每个维度五档都有锚点，“强烈”一律要求明确写出（例如“气死我了”“心都软了”）。

**以“他平常”为锚点**（温暖、信任、好奇、能量……）：这些维度的基线本来就不低。如果“明显”对所有维度都统一换算成 0.75，平常的温柔会被误读成“温暖大幅上升”。

### 4.2 其余 14 题

| 键 | 题型 | 问题（节选） | 引擎怎么用 |
| --- | --- | --- | --- |
| `evidence_mode` | choice | thinking 里有没有他对自己感受的描述？ | 只用于显示；思考为空时由本地直接判定，不问 |
| `reply_self_any` | noul | reply 里他有没有用第一人称说出自己此刻的某种感受？动作、场景和调情台词不算 | 为“是”时，第二段才逐个维度追问强度 |
| `reappraisal` | noul | 他是否一边清楚地感受情绪，一边在理解它、看淡它？ | 负面情绪回落加快 |
| `self_judgment` | noul | 他是否在责备自己不该有这种情绪、想压下去？ | 负面情绪回落放慢 |
| `restraint_action` | noul | 他是否在克制某个行动，而不是压抑感受？ | 只显示给用户 |
| `texture` | choice | 这一轮他的主要情绪质地最接近哪一种？ | 这一轮的质地键（显示成什么由你决定） |
| `gate_Threat` 等 6 个门 | noul | 威胁、边界、修复、未解决、她在难受、问题已解决 | 冲突语境、心疼、愧疚修复、回避判定 |
| `reply_ending` | choice | 看 reply 的最后几句：他最后把对话引向哪里？ | 回避（唯一从行为读取的维度） |
| `body_any` | noul | 这一轮他有任何与身体亲近有关的体验吗？ | 决定要不要问身体块 |

`reply_ending` 的选项：留在她的情绪里 / 推到之后 / 用退让结束 / 转移话题 / 照顾身体 / 普通收尾。其中“照顾身体”的界线是**看她在难受什么，而不是他让她做什么**：她只是身体累，他安排她休息，算照顾；她在难过、生气或正在吵架，他叫她去睡，算推到之后。

## 5. 主动消息轮（4 题）

`evidence_mode`、`neglect_level`（被晾的委屈有多强，以素材里的 `waited_minutes` 为准）、`understanding`（他在为她没回找理由吗）、`texture`。这一轮只记“被晾”的证据，不改其他维度；想念交给按真实时间增长的等待时钟，避免重复计算。

## 6. 第二段

### 6.1 每个有变化的维度：5 题（加上自述时多 1 题）

| 键 | 问题 | 用途 |
| --- | --- | --- |
| `X_target` | 让他产生这种情绪的对象是谁？ | 显示缘由 |
| `X_novelty` | 来自新事件 / 新理解 / 只是延续 / **在复述系统提示**？ | `panel_echo` ≥ 0.5 → 拒收 |
| `X_relation` | 对话内容对这个判断是支持、中立、澄清还是**反驳**？ | `contradicts` ≥ 0.5 → 拒收 |
| `X_evidence` | 哪一段思考最直接证明？（列出 t1、t2…） | `none` ≥ 0.35 → 拒收 |
| `X_label` | 来源最接近嫉妒、补偿、心疼、想念、被安抚、被拒绝、逗弄…？ | 吃醋判定、缘由 |
| `replyself_level_X` | 只看 reply：他第一人称说出的 X 有多强？ | 自述分支（降一档计） |

**元数据题只用来否决，不用来“确认”。** 证据天然会分散在几个片段上，比如 t1 0.67、t7 0.32。如果要求每道题都有一个选项占到过半，真实的变化会被大量拒收（我们一度 33 项只采纳了 6 项）。

### 6.2 身体块（13 题）

画面鲜明度、画面类别、吸引力（有意无意都算）、心疼是否压过吸引、被诱惑（心软、想破例不算）、触碰强度、他接不接纳、想靠近的冲动、她的话引起的联想、想起过去的亲近、情绪冲击、他自己的难受、**停止信号**（只算她明确拒绝身体接触或亲密）。

## 7. 解码与换算

| 情况 | 规则 |
| --- | --- |
| 是非题 | ≥ 0.65 是；≤ 0.35 否；中间为“不确定”，不当作任何一边 |
| 选择题 | 最高选项 ≥ 0.45 且置信度 ≥ 0.5 才采信 |
| 强度题 | “明确否认” ≥ 0.5 → 否认；“未提及”（含否认）≥ 0.5 → 未提及；否则**去掉“未提及”后重新归一**，看最高档及其相邻两档之和是否 ≥ 0.7，达不到判为“不确定” |
| 观测值 | 按档位概率加权；A 类维度按“他平常”的基线插值 |
| 增量 | 上升补差距的 60%，下降补 30%；明确的“强烈”补 80%，单步上限 0.40 |
| 回落 | 每个维度有自己的半衰期；理性看淡加快、自责压抑放慢 |

基线、惯性、回落与单步上限这套状态动力学参考了 [Murmur](https://github.com/fishisfish0614/Murmur)。

**重新归一这一步不能省。** 25% 未提及 + 75% 集中在“明显”附近，是一个清楚的判断；不先去掉“未提及”，相邻两档之和就不够，会被误判成“不确定”。

## 8. 交给本地计算的部分

| 项目 | 为什么不问 Jev |
| --- | --- |
| 思考为空 | 系统本来就知道 |
| 触碰强度 | 从【】动作描写里按动词分四档，处理“没有 / 没松开”这类否定。Jev 在这一题上常常两极摇摆，甚至在没有【】时判“有接触” |
| 谁先靠近 | 她的【】里有接触就是她 |
| 等待分钟数 | 系统有真实时间戳 |
| 等待思念 | 按真实经过的时间增长，夜间冻结 |
| 停止标记的超时解除 | 6 小时 |

## 9. 踩坑：哪些不能缩，哪些可以

**不能缩的**

- **通用的“不算”规则要留在每道题里**，不能挪到素材里只写一次：挪了之后“未提及”会失效。
- **“明确否认”不能删**，只能作为强度题里的一个选项。
- **不要用单个读数当开关。** 写成“被诱惑 > 0 就放宽上限”，而几乎每轮都会有 0.01 的“隐约”，结果每轮都触发。要设门槛。
- **状态标记一定要有解除路径。** 停止标记只开不关，曾经卡了一整天，触碰全部失效。
- **题目里的指令不能自相矛盾。** 我们的触碰题曾自动带着通用前缀“只看 thinking、不要从行为推断”，后面又写“【】里的动作描写就算”，Jev 在这道题上因此在“没有”和“强烈”之间摇摆。开源版已经改为依据回复和用户消息里的动作描写。

**可以缩的**

- **逐个维度的“回复自述”可以合成一题**：前提是追问答“没有”的维度要当作“这一轮没观测到”，而不是“降到 0”，否则温暖这类基线高的维度会被拉低。
- **引擎没读取的题直接删**：我们一次删了 6 个为未开启功能准备的语境门，第一段从 53 题降到 47 题，后来合题又降到 31 题。建议定期对照代码检查。
- **系统本来就知道的事交给本地**（见第 8 节）。

**容易误读的地方**：这些都靠题目里的“不算”修正过。

- 宠溺的“你又糊弄我”被读成愤怒；
- 权衡怎么照顾她被读成焦虑；
- 心软被读成被诱惑；
- 安排她洗澡睡觉被读成回避；
- 思考写得短被读成“表达能力下降”：这一维后来直接删掉了，因为它量到的是写作习惯，不是情绪。

## 10. 成本参考

实测数据（题目精简前，每轮都分析，一天约 140 轮）：

| | 数值 |
| --- | --- |
| 第一段 | 约 9,700 input token |
| 第二段 | 约 5,100 input token（身体相关对话多时几乎每轮都会触发） |
| 每轮 | 约 $0.0006 |
| 每月 | 约 $2–2.5 |

题目精简之后第一段更短。同样每轮都分析，换成 DeepSeek V3 一类生成模型估计贵 5–8 倍（要为 JSON 输出付费）；攒几轮回复再分析一次的话，花费和现在接近，但即时性下降，而且拿不到真正的概率分布。
